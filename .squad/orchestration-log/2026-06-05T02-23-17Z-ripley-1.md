### ❌ Blocking Issue

**Cold-cache create path can still fail before metadata is ready.**

The create hooks require entity metadata to add newly created records to solutions, but save buttons are not gated on metadata readiness. On fresh load:
1. `useEntities()` returns undefined until query settles
2. User saves before metadata query completes
3. Mutation path reaches `ensureComponentType()` without resolved numeric value
4. Operation fails

**Evidence:**
- `src/hooks/useEntities.tsx` exposes undefined until metadata present
- `src/services/EntityService.ts` throws when componentType not number
- Save buttons only depend on validation/pending state, not metadata readiness

## Required Revision Direction

Keep runtime metadata approach; close cold-cache gap by:

1. **Option A:** Disable solution-scoped save until entity metadata loaded, OR
2. **Option B:** Make create mutation unconditionally await metadata query before create/add-to-solution

**Preferred:** Centralize component-type resolution so five hooks don't duplicate fallback logic.
